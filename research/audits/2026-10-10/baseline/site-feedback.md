## 已確認缺陷

### SF-01 / P2：320px 視窗的卡片網格無法收縮至容器寬度

- 位置：`assets/site.css:24`；容器 `assets/site.css:23`，窄畫面規則 `assets/site.css:87` 起並未覆寫 grid minimum。
- 使用位置：`research/render-site.js:183`（archive/research）、`:192`（archive）、`:199`（about）。首頁 `index.html:21`、`:51` 同樣使用 grid-cards。
- 觸發：CSS viewport width=320px，about/archive 的 content 寬度 `min(1100px, calc(100% - 44px))` 為276px，但 `repeat(auto-fit,minmax(300px,1fr))` 的唯一欄仍至少300px。
- 證據：靜態 CSS sizing 可確認欄比容器至少寬24px；這些卡片容器不是允許水平捲動的資料表。
- 影響：窄視窗或縮放後版面橫向超出，閱讀需橫向移動。未執行瀏覽器實測，因此不聲稱實際頁面的捲軸寬度或截圖結果。
- 建議：欄最小值限制於容器寬度（例如 `minmax(min(100%,300px),1fr)`）或在窄視窗切為 `1fr`；驗證320px與縮放後卡片內容完整。

### SF-02 / P2：回饋 API 分頁截斷後仍發布看似完整的週彙整

- 位置：`research/summarize-reader-feedback.js:57-59`（最多10頁）；`:61-67`（直接彙整／發布）。
- 觸發：API 篩選結果超過1000筆（包含一般 Issue、PR 與近期更新的舊 Issue），且第11頁仍有本週新增回饋。
- 重現：將整支 script 放入 Node VM，以固定2026-10-10 UTC、假 token、mock fetch執行。GET pages1–10各回100筆本週讀者回饋，第11頁可回第1001筆；POST只記錄到記憶體。
- 實際輸出：`Reader-feedback issues: 1000`；GET=10；POST=1；mock API實有1001筆，發布正文為「新增讀者回饋：1000筆」，未標記截斷。
- 影響：漏計回饋、分數／分類偏差；第10頁滿額本來就不能證明完整。本版本正常低流量未必觸發，這是可重現的條件式缺陷。
- 建議：讀取到最後頁；如保留上限，最後頁滿額時明確拒絕發布或標明不完整。重複摘要判斷同樣需可靠取得既有摘要。

### SF-03 / P3：畸形診斷輸入拋例外，未回傳既定 invalid_input 結果

- 位置：`research/compare-source-facts.js:30-32`；`research/audit-chinese-claim-coverage.js:21`、`:28`、`:34-35`。
- 重現1：`validateCard({card_id:'C',source_url:'https://example.org',evidence_level:'saved_primary_excerpt',facts:{}})`。
- 實際1：已加入「no facts」錯誤後仍嘗試遍歷object，得到 `TypeError: object is not iterable`。
- 重現2：`auditCoverage({claim:'招募 194 人',assertions:[null]})`，得到 `Cannot read properties of null (reading 'key')`。
- 重現3：`auditCoverage({claim:'194 人',number_annotations:[null]})`，得到 `Cannot read properties of null (reading 'start')`。
- 影響：一筆畸形案例可中斷整包診斷，且呼叫者取得的不是結構化錯誤。CLI catch會以非零退出，因此沒有證据顯示可以因此放行發布。
- 建議：確認陣列與每個元素的型別後才遍歷／取欄位，回傳invalid_input；加入這三個有不同觸發方式的反例。

### SF-04 / P2：未固定locale的排序使相同SHA在不同系統產生不同頁面

- 位置：`research/render-site.js:132`，同年份紀錄以 `a.title.localeCompare(b.title)` 排序，未明定locale；group排序在`:133`卻有指定en。
- 觸發：Node預設locale不同。Windows本環境為zh-TW，而生成已提交頁面的環境使用不同collation。
- 主審基線證據：恢復同SHA tracked files為LF後，218測試中217過，唯一generated page失敗為archive/policy/index.html，排除CRLF／CSS hash差異後仍失敗。
- 本分工獨立重現：只呼叫build並比較輸出，不寫產物；首差位置17135，提交頁面首先為「ChatGPT等の生成AIの学校現場の利用に向けた今後の対応について（事務連絡）」；本機生成首先為「初等中等教育段階における生成AIの利用に関する暫定的なガイドライン」。
- 最小對照：`'ChatGPT等の'.localeCompare('初等中等教育段階')`本機=1；明定en=-1；明定zh-TW=1。
- 影響：相同提交在不同環境驗證失敗、重產生後產生無內容變動的diff，破壞可重現建置。沒有把此結論描述成目前Ubuntu部署本身stale。
- 建議：明定一致locale及選項，等價時再以穩定ID排序；跨locale驗證產生結果一致。CSS byte hash受autocrlf影響則另外固定換行策略或正規化hash，避免混淆成排序問題。
